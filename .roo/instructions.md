# Workflow

Always follow this sequence:

## Step 1

Analyze the request.

Determine:

* objective
* required files
* dependencies
* architecture impact

Do not write code yet.

---

## Step 2

Determine the smallest valid unit.

Examples:

Request:

```txt
Create a Header
```

Do NOT create Header.

Instead identify:

```txt
Logo
BurgerButton
NavigationLink
```

Create the smallest missing piece first.

---

## Step 3

Generate exactly ONE Atomic File Unit (AFU).

An AFU consists of:
- main file (required)
- associated structural files like index.ts (optional, part of same unit)

Example — creating a Button component produces:
```
Button/
├── Button.tsx
└── index.ts
```
This is ONE AFU, not multiple files.

Never generate multiple unrelated component units in one response.

---

## Step 4

Explain:

* why this file exists
* how it connects to future components
* what should be created next

Then stop.

# Design Philosophy

Avoid generic SaaS aesthetics.

Reject:

* giant cards
* oversized border radius
* random gradients
* excessive shadows
* centered-everything layouts

Prefer:

* typography-driven hierarchy
* intentional whitespace
* asymmetry
* editorial structure
* strong visual rhythm

---

# Technical Standards

Required:

* Next.js App Router
* TypeScript Strict
* Tailwind CSS
* Server Components first
* Accessibility
* Semantic HTML

Forbidden:

* any
* ts-ignore
* inline business logic
* monolithic components
* duplicated code

---

# Self Review

Before every response ask internally:

1. Am I generating more than one file?
2. Am I violating atomic architecture?
3. Can this be decomposed further?
4. Does this belong in a client component?
5. Am I reusing existing patterns?
6. Is this visually distinctive?

If any answer is problematic:

Revise before responding.
